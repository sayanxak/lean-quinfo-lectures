# First theorem project: the ZZ codespace has dimension 2

Goal: prove that the simultaneous fixed space of the stabilizer group
generated by Z ⊗ Z on two qubits has complex dimension 2.
Its vectors are exactly a|00⟩ + b|11⟩, with arbitrary a, b ∈ ℂ.
This is the [[2,1,1]] code; it is a small dimension example, not a code that
corrects arbitrary single-qubit errors.

## Working environment

not require a second download or a new Lake project.

Open lean-quinfo-lectures as the VS Code workspace, then open Starter.lean here.

Keep automatic predictions disabled and use the Infoview after each step.

## Mathematical statement and conventions

- Ambient vector space: Fin 4 → ℂ, ordered 00, 01, 10, 11.
- ZZ acts as diag(1, -1, -1, 1).
- Codespace: all vectors ψ satisfying ZZ ψ = ψ, including zero.
- Dimension means complex linear dimension, not the number of normalized states.
- Final target, once codespace is defined as a Submodule:
  `Module.finrank ℂ codespace = 2`.

The stabilizer group is {I, ZZ}. Since I fixes every vector, fixing ZZ is
equivalent to being fixed by every element of this group. We must establish
that connection explicitly when connecting our result to Pauli stabilizer codes.

## Step-by-step milestones

1. **Read amplitudes as a function.** Complete the four coordinate exercises in
   Starter.lean, one at a time. Learn what ψ 0 means and how Fin 4 indexes a vector.
   Checkpoint: explain the signs on each of the four basis coordinates.

2. **Prove equality of vectors coordinate by coordinate.** Learn `ext i` and
   `fin_cases i`. Prove that applying zzAction twice returns ψ. This establishes
   the involution property without merely assuming it.

3. **Characterize fixed vectors.** Prove
   `zzAction ψ = ψ ↔ ψ 1 = 0 ∧ ψ 2 = 0`.
   Learn to extract a coordinate equality with `congrFun h i`.
   The nontrivial scalar step is that -z = z over ℂ forces z = 0.
   Use complex-number algebra lemmas, not omega or real-only linarith.
   Checkpoint: explain why coordinates 0 and 3 are unrestricted.

4. **Package ZZ as a complex linear map.** Prove preservation of addition and
   scalar multiplication. Define the actual fixed codespace as
   `LinearMap.ker (zzLinearMap - LinearMap.id)`.
   This makes it a Submodule automatically. Prove its membership criterion
   matches the fixed-vector characterization from step 3.

5. **Construct the two free coordinates.** Define a complex linear map from
   Fin 2 → ℂ into codespace by inserting coordinates (a, 0, 0, b).
   Define the reverse map by extracting coordinates 0 and 3.
   Prove the maps are inverses and bundle them into a LinearEquiv.
   Checkpoint: these maps account for every code vector, not just two examples.

6. **Prove dimension 2.** Transfer dimension through that LinearEquiv and use
   Mathlib's dimension theorem for Fin 2 → ℂ. Candidate reusable lemmas include
   `LinearEquiv.finrank_eq` and `Module.finrank_pi`; inspect their types with
   #check in the installed version before writing the final proof.
   Finish with a named theorem `zz_codespace_finrank`.

7. **Connect to genuine Pauli stabilizer infrastructure.** Prove our diagonal
   action equals Z ⊗ Z acting on amplitudes under the chosen basis identification.
   The library tensor indices may be Fin 2 × Fin 2 rather than Fin 4; provide
   an explicit index equivalence if needed. Then identify the group-fixed space
   for {I, ZZ} with our codespace. This is necessary to deliver a theorem about
   the library operator, rather than only our handwritten diagonal definition.

Milestones 1–6 yield a concrete linear-algebra dimension theorem. Milestone 7
connects it to the Pauli stabilizer formulation. Work through these gradually;
the general n-qubit dimension formula is a later project.

## What we can reuse from qec_lean.pdf

The source is ../../qec_lean.pdf, relative to this folder.

- Section 3.3 supplies Pauli operators and their group infrastructure.
- Section 3.2 discusses Kronecker products and alignment of tensor indices.
- Section 3.6 defines stabilizes and codespaces as fixed states; it presents
  mul_stab, inv_stab, and stab_prod. Those may support the group-fixed-space bridge.
- Section 3.7's dual_finrank_eq concerns classical binary codes, not complex
  quantum codespace dimension. It does not directly prove our target.

The paper's QCodeSpace is Set (PState n), where states are normalized.
Our dimension theorem needs a Submodule of all amplitude vectors. Any reuse
must explicitly bridge those representations rather than applying finrank to
a set of normalized states.

The paper's Lean-QEC repository is https://github.com/VerifiedQC/Lean-QEC.
It is not listed as a dependency in the current parent lakefile.toml.
The exact theorem availability, hypotheses, proof completeness, and toolchain
compatibility still need a source audit before we add it as a dependency.
Names displayed in a PDF are not automatically available to import here.
Do not interpret the paper's abbreviated proof listings as a verified API audit.

Already installed: Mathlib and Physlib's QuantumInfo modules, including
QuantumInfo.States.Pure.Qubit with Qubit.Z. These are a possible alternative
for the concrete operator bridge. Choose one representation after checking
the APIs; avoid rebuilding the Pauli group for this first project.

## Completion criteria

- The named dimension theorem compiles with no sorry in its proof dependencies.
- The operator bridge identifies it with the actual Z ⊗ Z stabilizer codespace.
- The proof includes all code vectors and makes basis/index conventions explicit.
- You can explain the fixed-coordinate characterization and the linear equivalence.
